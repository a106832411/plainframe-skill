## 二、它们共用的五条工程方法

### 1. 画面是 `t` 的函数

pdoom 的说法最准确：**每一帧是歌曲时间的确定性函数**，所以浏览器预览和离线 1080p60 导出完全一致。
mg-styles-15 用 `window.renderAt(t)` 统一入口，无头 Chrome 逐帧截图，ffmpeg 合成。

→ 我们现在的 GSAP `seek(t)` 是同一件事，但要保证**任何随机都带种子**，否则预览和导出会对不上。

### 2. 风格是一个可交付单元

Lemo 的结构是三层：

```
DIRECTOR.md    怎么导：故事、声音、节奏、镜头、表演、自检
TECHNIQUE.md   怎么建：逐帧渲染、配音、配乐、混音
styles/<名>/STYLE.md   这个风格长什么样、听起来什么样；故事是你的
```

每种风格还配一支样片。**风格不是一句形容词，是一份可执行的说明 + 一支能看的片。**

→ 我们的 18 套风格只有参数，没有样片，也没有 STYLE.md。

### 3. 声音也是代码

mg-styles-15 的每条片子都有 `audio.py`，用采样合成配乐和音效，**音效和画面用同一套 cue**。
pdoom 更极端：Demucs 分轨 + CTC 强制对齐 + Whisper 交叉验证，得到逐词时间。

→ 我们的 BGM 是整段合成，音效和画面 cue 没绑在一起。

### 4. 自检是流程的一部分

- CAB：渲染接触表，模型自己看自己的帧；
- mg-styles-15：每条片过两轮 AI 评审，按 rubric 打分（最终 7.57–8.21）；
- Lemo：开场先问“要不要先看分镜”，要就停下来给你看关键镜头。

→ 我们的接触表是临时截的，没做成固定工具，也没有第二遍评审。

### 5. 一个角色 / 母题可以横跨所有风格

Lemo 的 OPUSCAR 98：同一只 Clawd 走过 98 届奥斯卡最佳影片，每部换一种画风。
角色不变，风格变——这样观众认得出是同一个系列。

→ 我们每条片子都换主角，系列感弱。

## 三、我们直接采纳的四件事

1. **给每套风格补 `STYLE.md` + 一支 10 秒样片**（先补常用的 6 套：鎏金、深空、极光、蓝图、报纸、像素）。
2. **`seek(t)` 纯函数化**：所有随机数用固定种子，预览与导出必须一致。
3. **音效挂 cue**：在 `synth_bgm.py` 里加 `cues.json`，关键动作（砸入、计数、盖章）在同一时间点出音效。
4. **自检工具化**：`tools/contact_sheet.py`（抽帧拼图）+ 二轮评审 rubric（照 CHECKLIST 打分，低于 7 分重修）。

## 四、不学的部分

- **不引入 three.js / Blender**：我们的流程是 HTML+GSAP，2D 足够，加 3D 会把构建和渲染链拉长一倍；
- **不追 60fps**：口播片 30fps 足够，60fps 只在推拉镜头多的片子里开；
- **不做逐词卡拉 OK**：我们是旁白片，逐句对齐已经够用。
