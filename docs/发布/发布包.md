# 发布包：标题、话题、封面、文案

一条片子做完了，出去之前要过的全部东西。**标题与话题只在这里定义一次**，别处只引用，不重写。

顺序：先定标题 → 配话题 → 出两张封面 → 写配文 → 过一遍末尾的检查。

---

## 一、标题

固定开头 `Vibe知识大赏｜`，后面接三段式：

```
Vibe知识大赏｜【现象】，不是【误因】，是因为【机制】。
```

示例：

> Vibe知识大赏｜傍晚太阳压到地平线，整片天变橙红，不是太阳自己变红了，是因为蓝光在半路就被空气弹光，只剩红橙走到你眼睛里。

**三个空位各写什么：**

| 空位 | 写什么 | 判据 |
|---|---|---|
| 现象 | 一句能被验证、画面上看得到的事 | 「整片天变橙红」，不是「天空变色」 |
| 误因 | 观众此刻脑子里的解释 | **一定得是观众真会那么想的**；没人信，整句就塌 |
| 机制 | 一句话讲清真正原因 | 不许出现术语，用动作或比喻（「蓝光被弹光」） |

**长度**：≤40 字（含 `Vibe知识大赏｜` 前缀）。抖音只露前两行，前两行要能独立成立。

**三种变体：**

```
A 时间跨度版  Vibe知识大赏｜【现象】吵了【N】年，不是因为没人研究，是因为【难点】。
B 人物版      Vibe知识大赏｜1963 年那个孩子没算错，不是因为运气，是因为【机制】。
C 机制版      Vibe知识大赏｜【现象】，不是因为【直觉解释】，是因为【机制】。
```

## 二、话题

三条，第一条固定，后两条按片子换：

```
#Vibe知识大赏 #<领域> #<具体词>
```

| 位置 | 作用 | 示例 |
|---|---|---|
| 第一条 | 活动话题，**固定**，每条必带 | `#Vibe知识大赏` |
| 第二条 | 领域，按选题换 | `#科普` `#天文` `#工程` `#人体` |
| 第三条 | 具体词，越具体越容易被搜到 | `#瑞利散射` `#晚霞` `#影子` |

想要泛流量可以把第三条换成 `#冷知识`、`#涨知识`，但**默认用具体词**：搜索量小，转化更准。

## 三、封面

两种规格，同一套版式；两张都放工程 `发布/`，**不进 `成品/`**（成品只放成片）。

| 规格 | 尺寸 | 用在哪 | 模板 |
|---|---|---|---|
| 16:9 | 1920×1080 | 横屏发布、播放页、B 站 / 西瓜 | `templates/cover-16x9.html` |
| 3:4 | 1080×1440 | 抖音信息流、主页封面 | `templates/cover-3x4.html` |

**版式规则：**

- 左边标题两行，主色词单独上色（「蓝」用蓝、「红」用橙），字号 16:9 用 112px、3:4 用 104px；
- 标题下一行副题（一句机制），再下面一个描边标签框（一句结论）；
- 右边或底部放主视觉（太阳、地平线），地平线压到画面 80% 高度，太阳只露半轮；
- 顶部 mono 小字放时长 / 编号，底部留一句「看完得到什么」；
- 背景用片子同一套渐变，不要另起一套色。

**出图：**

```powershell
$chrome = "<chrome-headless-shell 路径>"
& $chrome --headless --disable-gpu --hide-scrollbars `
  --window-size=1920,1080 --screenshot="封面-16x9.png" --virtual-time-budget=4000 "cover-16x9.html"
& $chrome --headless --disable-gpu --hide-scrollbars `
  --window-size=1080,1440 --screenshot="封面-3x4.png" --virtual-time-budget=4000 "cover-3x4.html"
```

## 四、配文

### 4.1 项目简介（仓库 / README 用）

**句式**

> 【一句话说清它是做什么的】：【输入什么】→【输出什么】。

**要点三条**（每条一句，不超过 25 字）：

| 位置 | 写什么 |
|---|---|
| 1 | 最反直觉的那个做法 |
| 2 | 用户最能感知的那个结果 |
| 3 | 可复用的资产（模板 / 风格 / 脚本） |

### 4.2 短文案（朋友圈 / 即刻 / 小红书，80–120 字）

```
【做了什么】。
【最省事的一步是什么】——【具体到一个动作、一个数字】。
【可选的对比】：以前【X】，现在【Y】。
【结尾一句邀请或指向】。
```

句式：

- 做了个【东西】：【一句话功能】。
- 【输入】写完，跑【几条命令】，出来【结果】。
- 以前【耗时】，现在【耗时】。
- 最麻烦的不是【显眼的部分】，是【不显眼的部分】。

**短文案只放一个数字**，多了没人记。

### 4.3 长文（知乎 / 公众号 / 掘金）

四段，每段 150–250 字：

| 段 | 作用 | 写什么 | 不写什么 |
|---|---|---|---|
| 1 问题 | 让人点头 | 一个具体到次数、时长的痛点 | 不写「随着时代发展」 |
| 2 转折 | 给出做法 | 你换掉的那个环节 + 为什么 | 不堆技术名词 |
| 3 方法 | 证明可行 | 步骤清单（4–6 步）+ 一个关键细节 | 不写「非常简单」 |
| 4 结果 | 收尾 | 一个可验证的结果 + 一句限制条件 | 不写「未来可期」 |

每段的开头句式：

- 问题：`【场景】里，【某个动作】要重复【次数】遍。`
- 转折：`后来换了个做法：【新做法】。`
- 方法：`现在的流程是：` + 有序列表。
- 结果：`改【单位】的成本从【旧值】降到【新值】。`

结尾三选一：限制（`目前只适合【范围】`）／邀请（`模板在【位置】`）／反问（`你会怎么做？`）。

### 4.4 短视频口播引子（前 3 句）

一句反常识 → 一句方法 → 一句结果：

```
以前【做某事】要【时长】，现在【时长】。
因为我把【环节】换成了【做法】。
【一句话说清做法】。
```

| 变体 | 首句 |
|---|---|
| 反常识 | `【大家以为的做法】其实是最慢的。` |
| 数字 | `一条【内容】有【N】个卡点，手动要拖【时长】。` |
| 结果前置 | `【结果】我用了【时长】，方法只有三步。` |

### 4.5 一句话（标签 / 副标题）

| 变体 | 句式 |
|---|---|
| 极短 | `【做什么】，改一【单位】就重出【结果】` |
| 技术向 | `【技术 A】+【技术 B】组成的【内容】流水线` |
| 结果向 | `【数量】个【产出】，全部可复现` |

## 五、发之前检查

- [ ] 标题 ≤40 字，前两行能独立成立
- [ ] 「不是」后面那个原因，真的是观众会想的
- [ ] 「是因为」里面没有术语
- [ ] 话题三条，第一条固定是 `#Vibe知识大赏`
- [ ] 封面出了两张（16:9 与 3:4），标题、副题、标签一致，只换版式
- [ ] 封面缩到 375px 宽，标题还读得清
- [ ] 封面没压主视觉，放在 `发布/`，没混进 `成品/`
- [ ] 配文只留一个数字
- [ ] 没有「颠覆」「革命」「史上最」
- [ ] 第一句能让人知道「跟我有什么关系」
- [ ] 结尾给了具体动作或具体位置
- [ ] 全文删掉任何一段试试，不通就是空话
