# 商用与系列化

> 学自 [xiaoxiong20xx-code/sy-styles-20](https://github.com/xiaoxiong20xx-code/sy-styles-20)（肖雄 XIAOXIONG，MIT）。
> 它的强项不是渲染，是**把一个风格变成一门生意**：20 种风格 × 3 个行业 = 60 条 15 秒广告片，全部同一套引擎出。

---

## 一、风格不是作品，是「可复用的模板」

它是这么组织的：

| 期 | 内容 | 说明 |
|---|---|---|
| 第一期 | 20 种风格，每种一条 10 秒 | 证明「这个风格能跑起来」 |
| 第二期 | 同样 20 种风格，题材全部换新 | 证明「风格可复用，题材可换」 |
| 行业示例 | 每种风格 × 3 个行业，15 秒/条 | 证明「能卖」 |

第二期是最关键的一步：**同一个风格换题材再做一遍**，才说明它是模板，不是一次性的作品。

**对我们的用法**：18 套风格，每套至少配两支不同题材的片子。只做过一支的风格，标记成「未验证」。

---

## 二、风格 × 行业矩阵

它的 20 个行业示例用的是中小企业：咖啡店、民宿、律所、茶庄、中医馆、宠物店、智能锁……

这不是随便选的——**这些行业都要 15 秒的短视频，且没有预算请团队**。

| 维度 | 内容 |
|---|---|
| 风格 | 我们的 18 套（示波器 / 鎏金 / 蓝图 / 报纸 / 极简白 …） |
| 行业 | 咖啡、民宿、律所、茶庄、中医、宠物、锁具、健身、花店、牙科 |
| 时长 | 15 秒（信息密度刚好够说清一件事，也够短到有人买） |
| 变体 | 同一组「风格 × 行业」配三种镜头/叙事，避免三条一个样 |

**做法**：先挑 1 个风格 × 3 个行业做样板，跑通了再横向铺。别一上来做 60 条。

---

## 三、工作流要反过来：先出一帧，再渲整段

它的命令顺序值得抄：

```
node make.js list          # 看有哪些风格
node make.js still 09 6.5  # 只渲第 6.5 秒那一帧，看图
node make.js style 09      # 满意了再渲这 10 秒
node make.js reel all      # 最后才拼整条展示片
```

**我们现在的顺序是反的**：写完整片 → 渲 5 分钟 → 抽帧 → 发现问题 → 再渲 5 分钟。

改：**写完一场就渲那一帧**（`hyperframes snapshot --at <该场时间>`），确认构图再往下写。一次 `still` 十几秒，一次整片 5 分钟。

同理，改稿后只重渲改动的那一场，不重渲全片。

---

## 四、两条命令级的便利

| 它的命令 | 作用 | 我们的对应 |
|---|---|---|
| `make.js still <编号> <秒>` | 渲单帧看效果 | `hyperframes snapshot --at`（已有） |
| `make.js brand 张三 ZHANGSAN` | 把画面里的署名换成客户的 | 无 → **商用必须补**：署名从写死改成参数 |
| `make.js cover` | 用关键帧拼封面 | `templates/cover-*.html` + Chrome 截图（够用） |
| `make.js --hwgpu` | 硬件加速，3D 风格快很多 | 我们的 `-w` / GPU 探针（已有） |

## 五、一个我们没有的技术点：子帧叠加做运动模糊

它的 `render.js` 是「一帧截图 → 多张子帧叠加 → 出运动模糊」，所以镜头推拉时没有生硬的逐帧跳。

我们目前是单帧直出：GSAP 插值虽然平滑，但快速位移（甩镜、粒子爆发）会显得"硬"。

**暂不做**，原因是：hyperframes 的捕获链不一定支持多子帧叠加，硬做得改渲染器。记在这里，等真有甩镜需求再说。

---

## 六、不学的部分

- **Canvas / WebGL / 光线步进 3D**：它是纯 Canvas + 自研渲染器，我们是 HTML + GSAP + HyperFrames。3D 光影风格一条要渲 25–80 分钟，和"改稿两分钟"冲突。
- **100 条的大而全**：它是展示仓库，不是生产工具。我们需要的是"能反复改同一条"，不是"堆 100 条"。

---

## 七、一句话总结

**它的核心不是 20 个风格，是「风格 × 题材 × 行业」这个乘法，以及「先看一帧」这个节奏。**
前者我们还没有，后者我们有工具但用反了。
