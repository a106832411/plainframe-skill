# 插件 / 组合包打包说明

同一个包，四个平台各有自己的清单文件名。根目录的清单是给「直接读文件」的 Agent 用的；`platforms/` 下是给插件管理器用的。

| 平台 | 清单文件 | 放在哪 |
|---|---|---|
| 豆包（本地电脑模式） | `platforms/doubao/manifest.json` | 包根目录，重命名为 `manifest.json` |
| WorkBuddy | `platforms/workbuddy/plugin.json` | 包根目录，重命名为 `plugin.json` |
| Qoder | `platforms/qoder/qoder.json` | 包根目录，重命名为 `qoder.json` |
| DSH | `platforms/dsh/skill.json` | 覆盖根目录的 `skill.json` |

## 为什么要分开

「组合包」报错的根源是：插件管理器只认它自己的那一个清单文件名，而且要求清单里**显式列出这个包由哪些部分组成**（skill / prompt / asset / script / doc）。

我们的包是多文件的（18 个风格、9 个脚本、4 篇文档），只给 `SKILL.md` 会被判定为「没有声明组合包」。

四个清单里都有一段 `bundle`，就是这份声明：

```json
"bundle": {
  "type": "composite",
  "components": [
    { "type": "skill",   "id": "plainframe", "entry": "SKILL.md" },
    { "type": "assets",  "id": "styles",     "path": "styles" },
    { "type": "scripts", "id": "templates",  "path": "templates" },
    ...
  ]
}
```

## 打包命令

```bash
# 以豆包为例
cp platforms/doubao/manifest.json ./manifest.json
zip -r plainframe-skill.zip . -x ".git/*"

# WorkBuddy
cp platforms/workbuddy/plugin.json ./plugin.json
```

如果平台要求单文件上传，用 `dist/plainframe-all.md`（约 52 KB）。

## 清单字段说明

| 字段 | 作用 | 备注 |
|---|---|---|
| `id` / `name` | 唯一标识与显示名 | 不要用中文做 id |
| `version` | 语义化版本 | 与根 `skill.json` 保持一致 |
| `entry` | 主文档 | 必须指向 `SKILL.md` |
| `memory` | 每次会话先读的规则 | `MEMORY.md` |
| `bundle` | **组合包声明** | 缺这段就会报「没有声明组合包」 |
| `capabilities` / `permissions` | 需要的能力 | 读写文件、执行命令、联网 |
| `requires` | 运行依赖 | node / python / ffmpeg / npm 包 |
| `triggers` / `keywords` | 何时触发 | 用中文短语，别用单个词 |

## 还是被拒怎么办

不同版本的插件管理器字段名会变。把报错原文（或截图里的字段名）发我，我按它的 schema 改——不用重做，只改 `platforms/` 下对应那一个文件。
